# 週次レポートの生成パイプライン（銘柄側の仕様）

> 週次高配当株レポートのうち、**数字・銘柄・グラフ・スクレイピング**に関わる仕様はこの文書が持つ。
> **声（一言所感）・note の見せ方・公開の手順**は journaling 側 `~/Desktop/journaling/docs/weekly-report.md` にある。
> 分担の軸は「壊れたとき、どっちのコードを直しに行くか」。

## 全体の位置

毎週土曜 04:40 の cron が `run_pick_high_yield_stock.sh` を叩き、4段を直列で回す。

| 段 | 実体 | リポジトリ | 失敗したら |
|---|---|---|---|
| 1 | `pick_high_yield_stock.py` — 銘柄選定・スプレッドシート更新・LINE 通知（7〜10分） | get_stock | **fail-closed**。即座に LINE 1通を送って中断し、レポートを作らない |
| 2 | `note_report.py` — レポート本体・素材メモ・グラフ5枚を生成 | get_stock | fail-open。`FAILURES` に積む |
| 3 | `weekly_report_note.sh` — 所感の候補6本を Claude に書かせ、push して LINE 通知 | **journaling** | fail-open。`FAILURES` に積む |
| 4 | `post_to_note.py` — 所感入りの完成版を note の下書きに保存（公開はしない） | get_stock | fail-open。`FAILURES` に積む |

2段目以降は1つコケてもレポート本体と通知を残す。溜めた `FAILURES` は最後に**まとめて1通**だけ LINE に送る（無料枠は月200通）。失敗通知には `cron.log` の末尾15行が付く。

2〜4段はどれもスプレッドシートかレポート `.md` を読むだけなので、**いつでも単体で再実行できる**（疎結合）。

## journaling への書き込み口

get_stock 側が journaling の絶対パスを握っている。**依存は get_stock → journaling の一方向**で、journaling 側のコードは get_stock を一切参照しない。

| 参照元 | 参照先 |
|---|---|
| `note_report.py:51` `OUTPUT_DIR` | `journaling/note/reports/`（本体 `.md`・素材メモ・PNG5枚） |
| `post_to_note.py:50` `REPORT_DIR` | 同上（読み取り＋診断ダンプの書き出し） |
| `post_to_note.py:58` `SEND_LINE` | `journaling/scripts/send_line.sh` |
| `run_pick_high_yield_stock.sh` | `journaling/scripts/send_line.sh`・`journaling/scripts/weekly_report_note.sh` |

**journaling 側でこれらのパスを動かすと、get_stock が黙って壊れる**（週1の処理なので気づくまで1週間かかる）。journaling の `CLAUDE.md`「移動禁止のパス」がこの表と対になっている。動かすときは両方を同時に直すこと。

## 取りこぼしの扱い（1段目だけ fail-closed）

銘柄選定は日経の個別銘柄ページを**149件**取りに行く（高配当株50=50／累進=30／連続増配=69）。ここで区別すべきものが2つあり、扱いを分けている。

| 状況 | 判定 | 扱い |
|---|---|---|
| 会社名も株価も取れない | **ページ取得の失敗** | 10秒→30秒→60秒と間を空けて最大3回リトライ（`RETRY_WAITS`）。それでも取れなければ**例外で中断**し、レポートを作らない |
| 会社名・株価は取れて配当利回りだけ空 | **値の恒常欠損** | `None` のまま通す。利回り None は降順ソートで末尾に行き、上位20の候補に入らない |

1銘柄でも取りこぼすと「利回り上位20→上位10」の順位が別物になるので、**欠けたレポートを出すくらいなら出さない**。一方、日経のページ上で恒常的に利回りが出ない銘柄は実在するので、そこで毎週中断しては本末転倒になる——だから両者をページ単位で切り分ける（健全なページは会社名・株価・配当欄がそろって取れる）。利回りが欠けた銘柄は `cron.log` に「利回り欠損: <code> <会社名>」と出る。**毎週同じ顔ぶれなら想定どおり**で、見慣れない銘柄が混じったら疑う。

取得間隔は3秒＋0〜1秒のジッター（`FETCH_INTERVAL` / `FETCH_JITTER`。等間隔の連打は弾かれやすい）。取得に失敗したときは `error.log` に HTTP ステータス・レスポンス長・`Retry-After` を残す。**次に落ちたとき「間隔を伸ばせば済む話か」を推測でなく判定するため**。

> 2026-09-11 の事故：8130（サンゲツ）のページが一時的に丸ごと取れず、株価の `select_one` が素で `.text` を呼んでいたため例外終了。1段目が死ぬと後続が全部走らないので、**レポート・LINE・note 下書きのすべてが出なかった**。しかも当時は失敗が通知されず、本人が見に来るまで気づけなかった。

## `note_report.py` の責務

**スプレッドシートの3タブ（購入履歴／時価総額／配当推移）を読むだけ**で本文とグラフを作る。再スクレイピングはしない。fail-open（データ不足時は例外を投げず警告して終了）。

出力は `journaling/note/reports/` に固定ファイル名で毎週上書き（最新版が1セットだけ残る。公開済みのアーカイブは note 側が持つ）：

- `週次運用レポート.md` — 本体。載せるのは**集客に効くものだけ**（今週の買付／ポートフォリオの育ち具合／トレンドグラフ3枚／構成の円グラフ2枚）。全保有一覧・全セクター表は廃止済み
- `週次素材メモ.md` — 所感の下書き専用。**note には載らない**（`post_to_note.py` は本体しか読まない）。数字はすべて Python 側で確定させ、Claude には計算させない——Web 検索を許しているので、拾ってきた数字と本体が食い違うのを防ぐため
- `trend_*.png` 3枚・`pie_*.png` 2枚

本体の作り方で覚えておくこと：

- 冒頭に所感のプレースホルダ `<!-- AUTO_SHOKAN -->` を置く。3段目の `weekly_report_note.sh` がここを候補6本に置換する
- 末尾（免責の直前）に有料記事への CTA「## レポートの裏側」を毎週自動で載せる。定数 `FLAGSHIP_ARTICLE_URL`（`note_report.py:73`）が**空なら出さない**＝壊れたリンクを公開しない
- グラフの日本語ラベルは `_JP_FONT_CANDIDATES` をシステムのフォント一覧と突き合わせて解決する。見つからなければ英語ラベルにフォールバックして豆腐化を避ける

## 素材の出どころ

- **個別銘柄の値動き**は `holdings_history.csv` のスナップショット比較で出す。「時価総額」タブは毎週 `clear()` で上書きされるので、**先週の株価はここにしか残らない**
- **相場の指数**は `market_index.py` が日経の指数値一覧ページ（Selenium。requests だと 403）から取り、`index_history.csv` に追記して前週比を出す
  - TOPIX は入れていない：日経の指数サイトが持っておらず、日経電子版・JPX 側はログイン壁や JS 描画で安定して取れなかった。ポートフォリオの母集団が日経の3指数（高配当株50／累進高配当株／連続増配株）なので、そちらを並べるほうが素材としても素直
- どちらの CSV も `.gitignore` で**明示的に追跡している**（`!holdings_history.csv` / `!index_history.csv`）。作り直せないため——時価総額タブは毎週上書きされ、指数も過去分を遡って取れない

### 行のキーは「実行日」ではなく「その値が属する営業日」

2026-08-07 の事故を受けて変更した。両方の履歴に共通の約束。

- **指数**は日経のページが持つデータ日付（`08.07(*大引)`）を営業日に直して使い、**確定値（終値・大引）しか記録しない**。前引や場中の時刻表示は捨てる。cron は引け後なので本番は必ず通り、昼に手で試した実行が履歴を汚さない。同じ営業日の行は上書きなので何度実行しても増えない
- **スナップショット**は配当推移タブの最新日付を使う（`_market_data_date`）。時価総額タブの上書きと配当推移への追記は `pick_high_yield_stock.py` が必ず同じ実行の中でやるので、この日付が「いま時価総額タブに入っている株価の営業日」になる

> 事故の中身：8/6 に手で `note_report.py` を走らせたら、時価総額タブがまだ 7/31 のままだったので **7/31 の株価が「8/6 の記録」として保存**され、翌日のレポートが「8/6 と比べて」「1日ぶんの動き」と書いた（実際は 7/31→8/7 の1週間）。指数側も日経平均だけ 8/6 前引・他は 8/5 終値、と1行の中で営業日が混ざっていた。

## 株式分割・併合の調整

マスタは `stock_splits.csv`（列: 証券コード, 効力発生日, 分割比率, 取得元, 備考）。分割比率は**「1株が何株になったか」**で、4 なら 1株→4株の分割、0.5 なら 2株→1株の併合。

- `pick_high_yield_stock.py` が毎週、**スプレッドシートの「購入履歴」タブそのものを書き換える**（取得単価 ÷ 比率・株数 × 比率。積＝実際に払った金額は変わらない）。直すのは効力発生日**より前**に買った行だけ。G列の備考に `[split 2026-07-30 x4]` というマーカーを残し、二重適用を防ぐ
  - ここを直せば下流（時価総額タブ・配当推移・銘柄選定の4%/20%上限・素材メモ）は全部シートを読むだけなので自動で正しくなる
- `note_report.py` は `holdings_history.csv` の過去スナップショットの株価も遡って調整する（`分割調整` 列にマーカー）。これをやらないと分割をまたいだ週の3節が毎回 −75% になる
- **「配当推移」タブの過去行は直さない。** 記録した時点では「分割前株価 × 分割前株数」で正しかったため
- マスタの更新は yfinance が自動でやるが、**連続アクセスですぐレート制限（`YFRateLimitError`）に当たる**ため fail-open にしてある。取れなかった週も既存 CSV ぶんの調整は効き続けるので、**取り逃したら CSV に手で1行足せばよい**
- `SPLIT_DRY_RUN=1` を付けて実行すると、書き込まずに差分だけ表示する
- 実例：三井住友トラストグループ（8309）は **2026-07-30 に1株→4株の分割**。放置していたとき取得来の損益が **−61.70%** と表示されていた（正しくは +53%）
- 素材メモの「要確認」は、マスタに無い分割を拾うための安全網：値動き（3節）は±30%超で上下とも、取得来の損益（4節）は **−50%超の下げだけ**（何年ぶんもの値上がりが混ざると比率で分割と見分けが付かず、素直に儲かった銘柄まで弾いてしまうため。取り逃した分割の症状は必ず下げ側に出る）

## `post_to_note.py` の運用

note には公式の投稿 API が無く、エディタは独自の JS ブロックエディタ。**note 側の UI 変更で壊れやすい**のがこのスクリプト。

- **headful 必須**（note のエディタは headless だと描画されない）。常駐機の Xwayland `DISPLAY=:0` を使う（スクリプトが未設定時に補うので cron でもそのまま動く）
- 初回のみ `python post_to_note.py --login` でログイン（2段階認証もここで通す）→ プロファイル `~/.note_profile` に保存
- 本文は markdown を**残したまま**ブロック単位で送る。note のエディタが入力ルールで自動変換するので、`## ` → 大見出し（h2＝目次に出る）／`- ` → 箇条書き／`**…**` → 太字 がそのまま反映される。画像は `![](…)` の位置にインライン挿入される（トレンド3枚＝トレンドグラフ節、円グラフ2枚＝構成節）
- 改行は `Keys.ENTER`（`"\n"` だと soft break で段落が割れない）
- **下書き保存まで。「公開に進む」は押さない**（公開前の目視ゲットを人間が通すため）

### セレクタが壊れたときの調べ方

`python post_to_note.py --dump`（実DOM を `note_dom_dump.html` / `note_dump.png` に書き出し）や `--probe-image`（本文画像挿入の仕組み）／`--probe-eyecatch`（見出し画像の設定）で調べ直し、`NOTE_SELECTORS` を合わせる。

確認済みの実DOM：

| 対象 | セレクタ |
|---|---|
| タイトル | `textarea[placeholder='記事タイトル']` |
| 本文 | `div.ProseMirror` |
| 画像挿入 | 本文「+」(`button[aria-label='メニューを開く']`) → 「画像」→ `input#note-editor-image-upload-input` |
| 下書き保存 | `//button[normalize-space()='下書き保存']` |

検証で作った空・重複の下書きは note の下書き一覧から手で削除してよい（毎週1本だけ残ればよい）。

## グラフ PNG は journaling 側で git 追跡外

`trend_*.png`・`pie_*.png`・`thumbnail.png` は journaling の `.gitignore` に入っている（2026-09-18。毎週上書きされるのに1回 450KB を履歴に積むため）。**ファイルは消さないこと**——追跡を外しただけで、`note/reports/` のディスク上には要る（`post_to_note.py` が読む）。詳細は journaling 側 `docs/weekly-report.md`「グラフは git の追跡外」。
